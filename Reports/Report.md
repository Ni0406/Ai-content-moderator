# Отчет по Серии Заданий 1: «Платформа модерации и анализа контента (AI Content Analyzer)»

**Цель проекта:** Разработка модульного приложения с использованием готовых (pre-trained) библиотек машинного обучения для решения прикладных задач анализа текста, изображений, аудио и видео, а также интеграция локальной LLM.

## 1. Преимущества выбранных библиотек
В проекте использованы три различных ML-фреймворка, каждый из которых является стандартом индустрии в своей нише:
*   **Hugging Face (`transformers`):** Выбран для NLP (анализ текста) и ASR (распознавание аудио). Главное преимущество HF заключается в наличии высокоуровневой абстракции `pipeline`. Она позволяет в несколько строк кода загружать веса моделей, токенизировать входные данные и получать готовый результат (end-to-end), избавляя от написания сложного boilerplate-кода.
*   **TensorFlow / Keras (`tf.keras.applications`):** Выбран для Computer Vision (классификация изображений). Преимущество Keras — предоставление удобных классов-оберток для популярных легковесных архитектур (например, MobileNet), которые включают в себя встроенные и оптимизированные функции предобработки тензоров (`preprocess_input`).
*   **PyTorch (`torch.hub`):** Выбран для детекции объектов на видео. PyTorch обладает высокой динамичностью вычислительного графа и является стандартом для интеграции сложных SOTA-моделей (таких как YOLO), разрабатываемых исследовательским сообществом.

## 2. Принципы работы моделей и причины их выбора
1.  **Текст (Анализ тональности) — `rubert-base-cased-sentiment`:**
    *   *Принцип работы:* Основана на архитектуре BERT (Bidirectional Encoder Representations from Transformers). Модель анализирует контекст слова с обеих сторон (двунаправленно) с помощью механизма внимания (Self-Attention).
    *   *Причина выбора:* Прекрасно работает с русским языком "из коробки", урезанная архитектура (base) обеспечивает быстрый инференс на CPU.
2.  **Изображения (Классификация) — `MobileNetV2`:**
    *   *Принцип работы:* Сверточная нейронная сеть (CNN), использующая глубинные разделяемые свертки (depthwise separable convolutions). Это радикально уменьшает количество параметров и математических операций.
    *   *Причина выбора:* Идеальный баланс между точностью и скоростью. Модель специально разработана для Edge-устройств с ограниченной вычислительной мощностью.
3.  **Аудио (Speech-to-Text) — `Whisper-tiny`:**
    *   *Принцип работы:* Трансформер типа Encoder-Decoder. Энкодер преобразует аудиосигнал (log-Mel спектрограмму) в скрытые представления, а декодер авторегрессионно генерирует текстовые токены.
    *   *Причина выбора:* Мультиязычность (отличная поддержка русского языка), высокая устойчивость к фоновому шуму. Версия `tiny` (39 млн параметров) работает локально без задержек.
4.  **Видео (Детекция) — `YOLOv5s`:**
    *   *Принцип работы:* You Only Look Once — модель анализирует всё изображение целиком за один проход, разделяя его на сетку и предсказывая bounding boxes и вероятности классов для каждой ячейки одновременно.
    *   *Причина выбора:* YOLO является SOTA в задачах real-time детекции. Версия `small` позволяет обрабатывать видео покадрово (FPS) с приемлемой скоростью даже без наличия GPU.
5.  **Локальная LLM — `Qwen-1.5B-Instruct`:**
    *   *Принцип работы:* Авторегрессионная языковая модель на базе архитектуры Transformer (декодер), оптимизированная под диалоговые задачи и следование инструкциям (Instruct).
    *   *Причина выбора:* Размер в 1.5 млрд параметров позволяет загрузить модель в оперативную память обычного ПК (около 1.6 ГБ RAM), при этом она демонстрирует превосходное понимание русского синтаксиса для задач суммаризации.

## 3. Структура датасетов
Так как в проекте использованы предобученные (Pre-trained) решения, модели базируются на крупнейших открытых датасетах, что гарантирует их высокую обобщающую способность:
*   **ImageNet** (для MobileNetV2): Более 1.2 млн аннотированных изображений, разделенных на 1000 бытовых классов.
*   **COCO (Common Objects in Context)** (для YOLOv5): Содержит более 330 000 изображений и 80 категорий объектов (люди, машины, животные и т.д.) со сложным фоном.
*   **Whisper Training Data:** 680 000 часов мультиязычных размеченных аудиоданных, собранных из интернета, что обеспечивает робастность к акцентам.
*   **RuSentiment / RuReviews** (для RuBERT): Корпуса русскоязычных отзывов из социальных сетей и e-commerce платформ для точного улавливания тональности.

## 4. Метрики оценки качества (Как оценить, что модель работает нормально?)
Для мониторинга эффективности системы модерации в продакшене определен следующий набор метрик:

*   **ML-метрики (Качество классификации):**
    *   *Accuracy (Точность):* Общая доля правильных предсказаний алгоритма.
    *   *Recall (Полнота):* Критическая метрика для модерации контента. Показывает, какую долю реального "негатива" (запрещенного контента) модель смогла отловить (снижение False Negatives).
    *   *F1-Score:* Гармоническое среднее между Precision и Recall (используется при дисбалансе классов).
    *   *mAP (Mean Average Precision):* Используется для оценки YOLO (насколько точно рамка совпадает с реальным объектом на видео).
*   **Продуктовые метрики (Бизнес-ценность):**
    *   *Resolution Time:* Среднее время модерации одного тикета (сокращение времени за счет AI).
    *   *Session Time:* Время, которое пользователь проводит в безопасной (отмодерированной) среде приложения.
*   **Инфраструктурные метрики (Производительность):**
    *   *Inference Time / Latency:* Время (в миллисекундах), затрачиваемое на обработку одного запроса (кадра/текста/аудио).
    *   *RAM/VRAM Usage:* Потребление оперативной и видеопамяти при загрузке весов моделей.
    *   *Throughput:* Пропускная способность сервера (например, FPS при обработке видеопотока).

## 5. Особенности реализации алгоритма и его эффективность
*   **Объектно-ориентированный подход (ООП):** Весь код спроектирован в виде изолированных классов (`TextAnalyzer`, `VideoAnalyzer`). Инкапсуляция логики загрузки моделей в метод `__init__` гарантирует, что "тяжелые" веса загружаются в оперативную память сервера **только один раз** при старте приложения, а не при каждом новом пользовательском запросе (Singleton pattern).
*   **API-ready архитектура:** Благодаря изоляции методов инференса (например, абстракция `analyze(text)`), любой из ML-модулей мгновенно интегрируется в REST API (FastAPI), что обеспечивает высокую масштабируемость микросервиса.
*   **Эффективность ресурсопотребления:** Выбраны исключительно легковесные архитектуры (MobileNet, YOLOv5**s**, Whisper-**tiny**). Это позволяет платформе успешно функционировать без наличия мощных GPU (инференс происходит на CPU), что делает развертывание системы экономически дешевым и отказоустойчивым.
