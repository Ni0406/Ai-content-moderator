## Часть 2: Рекомендательная система (RecSys)

Для реализации RecSys был выбран классический медиа-датасет **MovieLens 100K** (100 000 оценок от 1000 пользователей на 1700 фильмов).

### I. Реализованные подходы
**1. Базовая эвристика ("Популярное / Рекомендации по рейтингу"):**
Агрегация данных для вывода топ-N фильмов с наивысшим средним рейтингом (учитывались только фильмы с >100 оценок для статистической значимости).

**2. Content-Based Recommender System:**
Векторизация жанров фильмов с помощью `TfidfVectorizer` и расчет косинусного расстояния (`cosine_similarity`). Позволяет рекомендовать фильмы, семантически похожие на просмотренный.

**3. Collaborative Filtering (Item-Based):**
Построена матрица "Пользователь-Фильм". Рассчитана корреляция Пирсона для поиска паттернов: *"Пользователи, высоко оценившие этот фильм, также высоко оценивают..."*.

**4. Продвинутая модель (Two-Tower Architecture на PyTorch):**
Реализована современная архитектура "Двух Башен" (Retrieval модель).
*Блок кода (Архитектура Two-Tower):*
```python
class TwoTowerModel(nn.Module):
    def __init__(self, num_users, num_movies, embedding_dim=32):
        super().__init__()
        # Башня 1: Векторное представление пользователя
        self.user_tower = nn.Embedding(num_embeddings=num_users, embedding_dim=embedding_dim)
        # Башня 2: Векторное представление контента (фильма)
        self.movie_tower = nn.Embedding(num_embeddings=num_movies, embedding_dim=embedding_dim)

    def forward(self, user_id, movie_id):
        user_embedding = self.user_tower(user_id)
        movie_embedding = self.movie_tower(movie_id)
        # Dot Product для получения скора релевантности
        return (user_embedding * movie_embedding).sum(dim=1)
```
*Модель успешно обучена на датасете MovieLens (бинарная классификация, функция потерь BCEWithLogitsLoss снизилась с 2.34 до 2.25).*

### II. Проблемы, особенности и ограничения

#### a) Специфичные проблемы подходов
**Проблема 1: Холодный старт (Cold Start) в Collaborative Filtering.**
*   *Как решается?* Проведение небольшого onboarding-опроса при регистрации пользователя (выбор любимых жанров).
*   *Проблема решения:* Увеличение трения (friction) при регистрации, что ведет к раннему оттоку (drop-off).
*   *Рассуждение (Best Practices):* Оптимально использовать гибридный подход. Для новых пользователей без истории выдавать **Эвристику** (Топ самых популярных фильмов месяца), постепенно подмешивая Item-Based рекомендации по мере накопления их кликов/оценок.

**Проблема 2: Этические проблемы и Bias ("С этим часто покупают").**
*   *Как решается?* Внедрение фильтров и черных списков (blocklists) для предотвращения связывания нейтрального контента с токсичным или дискриминационным.
*   *Проблема решения:* Необходимость постоянной ручной модерации списков. Риск заблокировать релевантные рекомендации (False Positives).
*   *Рассуждение:* Идеальное решение — интеграция нашего **AI Content Analyzer** (разработанного в предыдущих сериях) как промежуточного middleware, который автоматически проверяет эмбеддинги рекомендаций на токсичность перед выдачей пользователю.

#### b) Проблемы в продакшене (Production)
**Проблема: Долгий отклик (High Latency) Two-Tower модели.**
*   *Как решается?* Модель не должна считать векторы в реальном времени. Векторы фильмов (Movie Tower) вычисляются заранее и кладутся в векторную БД (FAISS, RedisVL). При запросе считается только вектор юзера.
*   *Проблема решения:* Инфраструктурные затраты на оперативную память (RAM) для хранения миллионов векторов и риск рекомендаций неактуального (устаревшего) контента, если кэш обновляется редко.
*   *Рассуждение:* Использование архитектуры Approximate Nearest Neighbors (ANN) позволяет пожертвовать долями процента точности ради радикального ускорения поиска (миллисекунды вместо секунд).

## Часть 3: Холод работы, Сложности и Метрики

### 3.1 Ход работы и преодоление сложностей
В процессе выполнения СЗ_1–СЗ_3 мы столкнулись с рядом технических вызовов:
1. **Изоляция виртуального окружения (PyTest):** Ошибка `ModuleNotFoundError` при тестировании. Решена явным вызовом `python -m pytest` для привязки к локальному `.venv`.
2. **Несовпадение ключей (KeyError):** При переходе на русскоязычную модель `rubert-base-cased` изменился формат ответа. Решено внедрением слоя абстракции (маппинга ключей) внутри класса `TextAnalyzer`.
3. **Ад зависимостей LangChain:** Устаревание функций `initialize_agent`. Архитектура была полностью переписана на современный `create_agent` и `ChatOllama`.
4. **"Галлюцинации" LLM:** Компактная модель Qwen иногда выдавала мусорный лог или иероглифы. Решено внедрением парсера `reversed(messages)`, перехватывающего только чистый `AIMessage`.

### 3.2 Оценка работы в продакшене (Metric-driven approach)

Для отслеживания качества инфраструктуры внедрены следующие метрики:

**ML-метрики (Качество алгоритмов):**
- **Precision@K / Recall@K (RecSys):** Доля действительно интересных фильмов среди топ-K предложенных алгоритмом Two-Tower.
- **NDCG@K (RecSys):** Насколько релевантные фильмы находятся именно на первых позициях выдачи.
- **Accuracy / F1-Score (Модерация):** Точность классификации тональности текстов.

**Бизнес-метрики и Инфраструктура:**
- **CTR (Click-Through Rate):** Процент кликов пользователей по карточкам предложенных фильмов. Главный показатель заинтересованности.
- **Customer Retention Rate (CRR):** Метрика удержания. Показывает, насколько персонализация влияет на возвращаемость пользователей в приложение.
- **Generation Latency (LLMOps):** Время генерации ответа LLM агентом. Отслеживается через Langfuse для предотвращения таймаутов на фронтенде (целевое значение < 2 секунд).
- **Time/Cost Saved:** Количество часов ручной модерации контента, сэкономленных за счет внедрения AI Content Analyzer.
