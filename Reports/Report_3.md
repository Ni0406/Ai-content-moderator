# Отчет по Серии Заданий 3: LLMOps и RecSys

## Part 1: LLMOps (Observability)

### Этап 1: Сравнительный анализ стеков мониторинга

| Критерий | Langtrace | Langfuse | OpenLLMetry |
| :--- | :--- | :--- | :--- |
| **Особенности** | Фокус на OpenTelemetry. Хорошо подходит для энтерпрайза. | Специализирован для LLM-агентов. Отличный UI для трейсов и оценки. | Базируется на стандартном OpenTelemetry, универсален для микросервисов. |
| **Преимущества** | Нативная поддержка графов и сложных пайплайнов. | Идеальная интеграция с LangChain "из коробки". Встроенное версионирование промптов и подсчет стоимости токенов. | Не требует изменения кода (auto-instrumentation). Открытый стандарт. |
| **Недостатки** | Меньше специфичных LLM-метрик в базовой версии. | Требует явной передачи callback-ов в коде (при ручной настройке). | Сложная настройка дашбордов (нужно поднимать Grafana/Jaeger). |
| **Интеграции** | LangChain, LlamaIndex, OpenAI | LangChain, LiteLLM, OpenAI, Flowise | Любые системы, поддерживающие OTel |
| **Сложность интеграции** | Средняя | **Низкая (2 строки кода)** | Средняя |
| **Лицензия** | Open Source / Cloud | Open Source (MIT) / Cloud | Open Source (Apache 2.0) |

**Обоснование выбора стека:**
Для мониторинга ИИ-агента был выбран **Langfuse**. 
*Причины:* 
1) Он имеет нативную интеграцию с использованным нами фреймворком LangChain (через `CallbackHandler`).
2) Предоставляет готовые дашборды для специфичных LLM-метрик (расход токенов, latency каждого шага рассуждений ReAct-агента, стоимость).
3) Позволяет "провалиться" внутрь каждого вызова и посмотреть, какие инструменты (Tools) выбрал агент, что идеально для отладки галлюцинаций.
